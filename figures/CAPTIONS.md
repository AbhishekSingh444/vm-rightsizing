# Figure captions

Generated by `src/make_figures.py`. Every value is derived from the listed source; none is transcribed from a document.

## Figure 1 — `fig1_headroom.png` / `.svg`

Cumulative distribution of per-VM CPU and memory utilisation across the 792 usable VMs, each as a percentage of that VM's own provisioned capacity; verticals mark the 95th percentile of each distribution. The mass concentrated at low utilisation is the headroom this project reclaims. 164 VMs report CPU above 100%, a telemetry artefact that the baselines clip to the original allocation on load.

**Source:** `results/dataset_report.csv`

## Figure 2 — `fig2_reclamation_vs_safety.png` / `.svg`

Reclaimed vCPU, reclaimed memory and the share of VMs left violation-free, for each scope/method combination. p95 reclaims more than peak on both resources and pays for it in safety; the price is steepest for non-idle VMs.

**Source:** `results/baseline_summary.csv`

## Figure 3 — `fig3_safety_split.png` / `.svg`

Share of VMs left violation-free, split by resource. Memory safety falls far faster than CPU safety under the same recommendation, which is what justifies the asymmetric violation rule (memory terminal at one sample; CPU degrading, two consecutive samples).

**Source:** `results/baseline_summary.csv`

## Figure 4 — `fig4_exclusion_cascade.png` / `.svg`

Data-quality exclusion cascade, 1250 trace files down to 792 usable VMs, one bar per gate in the order load_vm applies them. The gates are not disjoint in the underlying data, so each VM is counted under the first gate it fails.

**Source:** `results/{dataset_report,bad_capacity_characterisation,below_catalog_floor_scan,capacity_shift_report}.csv + file count in data/fastStorage/`

## Figure 5 — `fig5_t8_validation.png` / `.svg`

Offline prediction against kernel outcome for the 50 cluster-replayed VMs. The like-with-like rule -- demand above the limit actually enforced -- reproduces the kernel's verdict with zero mismatches. The 4 VMs between the two thresholds exceed their recommendation but not the enforced limit, so this testbed cannot adjudicate them.

**Source:** `results/wave{1..5}_outcomes.csv`

## Figure 6 — `fig6_idle_contamination.png` / `.svg`

Pooled (capacity-hour-weighted) reclamation for idle versus non-idle VMs. Idle machines inflate the headline saving on both resources under peak (CPU +40.5pp, memory +45.3pp); under p95 the CPU gap stays wide (+38.4pp) while the memory gap nearly closes (+7.2pp), because an idle VM still carries a real p95 memory floor even with near-zero CPU. Note that idle inflates the POOLED figure while slightly depressing the unweighted per-VM mean, because idle VMs cluster at small sizes where the 2 GB catalog floor caps reclamation; docs/DATA_QUALITY.md example C derives this.

**Source:** `results/per_vm_results.csv + results/run_config.json (verified against results/baseline_summary.csv)`
